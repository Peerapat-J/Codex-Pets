# เพิ่ม pet ตัวใหม่

## 1. กำหนดตัวละคร

เลือก ID ภาษาอังกฤษตัวเล็ก เช่น `luna` หรือ `forest-mage` โดยไม่ซ้ำกับตัวเดิม แล้วใช้ [แบบฟอร์มตัวละคร](../templates/pet-brief.md) ระบุชื่อ รูปลักษณ์ สีหลัก อุปกรณ์ และท่าทางที่ต้องการ

เก็บภาพอ้างอิงใน `references/<pet-id>/` และรายละเอียดตัวละครใน `pets/<pet-id>/` ใช้พาธแบบ relative เพื่อย้าย repo ไปที่อื่นได้

## 2. สร้างและปรับภาพ

เปิด repo นี้เป็นโปรเจคใน Codex ที่มี skill `hatch-pet` และเครื่องมือสร้างภาพ พร้อมระบุ brief และภาพอ้างอิง ตัวอย่างคำขอ:

```text
$hatch-pet สร้าง pet ID luna ตาม brief และภาพอ้างอิงใน repo นี้
เก็บผลลัพธ์สุดท้ายใน pets/luna/ พร้อม preview และรายงาน QA
เก็บไฟล์ระหว่างสร้างใน work/luna/
```

ใช้ workflow และ validator ของ skill เวอร์ชันที่ติดตั้งอยู่ ตรวจข้อกำหนดของรูปแบบที่ Codex รองรับก่อนเริ่มตัวใหม่ โครงสร้าง v2 ของ Mira ดูได้ใน [brief.json](../pets/mira/brief.json)

## 3. ตรวจและเก็บผลลัพธ์

เก็บไฟล์ต่อไปนี้ใน `pets/<pet-id>/`:

- `pet.json` พร้อม ID ที่ตรงกับชื่อโฟลเดอร์และ `spritesheetPath` ที่ตรงกับไฟล์จริง
- `spritesheet.webp` ซึ่งผ่าน validator ของรูปแบบที่เลือก
- `README.md` พร้อม preview วิธีใช้ และข้อจำกัดที่ยังเหลือ
- Brief ที่ใช้สร้าง และ `qa/` สำหรับรายงานกับภาพตรวจ

ตรวจภาพที่ขนาดใช้งานจริง รวมถึงเฟรมวน การกะพริบตา ทิศวิ่ง ทิศการมอง ตำแหน่งตัวละคร และขอบโปร่งใส แยกผลตรวจอัตโนมัติออกจากการลองใช้งานใน Codex UI และระบุสิ่งที่ยังไม่ได้ลองไว้ตามจริง

เก็บ atlas ตัวสุดท้ายเพียงไฟล์เดียวในโฟลเดอร์ pet และเก็บ ZIP สำหรับแจกใน `dist/` ไฟล์ระหว่างสร้างใน `work/` ไม่เข้า Git หากมีภาพต้นแบบที่ต้องใช้ต่อ ให้คัดลอกภาพที่เลือกไว้ใน `references/<pet-id>/` ก่อนล้างไฟล์ระหว่างสร้าง

## 4. บันทึกเวอร์ชัน

เพิ่ม pet ลงตารางใน README หลัก ตรวจรายชื่อไฟล์และผลต่างก่อน commit ให้แน่ใจว่าไม่มีไฟล์ชั่วคราวหรือข้อมูลเฉพาะเครื่องปะปน แล้วสร้าง commit สำหรับ pet ตัวนั้น เช่น `feat: add Luna pet`

ก่อนแทนที่ pet ที่ติดตั้งอยู่ ให้เก็บสำเนาของเวอร์ชันเดิมไว้ การ push ไป remote ทำเมื่อพร้อมเผยแพร่การเปลี่ยนแปลง
